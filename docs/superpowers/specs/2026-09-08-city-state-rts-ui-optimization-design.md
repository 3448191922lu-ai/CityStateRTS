# 《城邦争霸》HUD 优化设计

## 背景

当前屏幕 HUD 主要由 `AStrategyHUD::DrawHUD` 即时绘制，城镇管理则使用独立的 `UStrategyTownPanel`。两者缺少统一布局，导致信息层级不一致、城镇面板与底栏争夺空间，且 Canvas 文本难以提供完整的按钮状态、悬停说明和分辨率适配。

本轮只优化屏幕 UI，不改变建造、训练、城镇专精、单位命令、迷雾、AI 或胜负规则。

## 目标

- 建立统一、清晰、稳定的传统 RTS HUD。
- 让玩家能快速读取资源、当前选择、状态、队列和可执行命令。
- 让小队、建筑和城镇共用一套固定布局，避免面板跳动与重叠。
- 保留键盘、鼠标右键、框选和世界小队徽记拖动的现有操作。
- 支持 1280×720 至 2560×1440 的常见 16:9 与 16:10 窗口。

## 非目标

- 不增加小地图、主菜单、科技树、任务系统或新的玩法规则。
- 不把战争迷雾、世界徽记、框选和补给线迁移为 UMG 控件。
- 不安装 UI 插件，不引入外部字体或复杂主题框架。
- 不重新制作暂停菜单的功能结构。

## 视觉方向

采用“城邦战术”风格：深蓝石板背景、低透明度战场遮罩、金色重点边框、克制的军事装饰。

- 金色：重点、可操作按钮和建设/训练进度。
- 绿色：有效放置、健康与成功反馈。
- 红色：危险、资源不足和无效操作。
- 蓝色：玩家阵营识别。
- 灰色：不可用按钮与次要说明。

界面文字统一使用中文。标题为 20–22 px，正文为 16–18 px；数字和快捷键加粗。悬停、选中和警告变化控制在 0.1–0.2 秒，临时通知约 3 秒淡出，不使用持续闪烁或大幅移动动画。

## 总体布局

### 顶部资源栏

资源栏固定在顶部中央，显示：

- 金币与每秒收入。
- 已用人口、预留人口与人口上限。
- 已占城镇与地图城镇总数。

资源不足或人口已满时，只让对应项目短暂变红，不弹出阻塞式窗口。

### 临时通知

通知位于资源栏下方，最多同时显示三条，按时间自动淡出。用于资源不足、人口已满、无效放置、专精完成及类似的离散反馈。通知不覆盖资源栏、世界小队徽记或底栏。

### 统一整底栏

底栏采用平衡型密度，基准高度约 104 px，固定分为三列：

1. 对象信息 24%。
2. 状态与详情 44%。
3. 可执行命令 32%。

选择对象时只替换三列内容，不改变底栏位置、尺寸或列比例。

底栏内容优先级为：

1. 建造放置状态。
2. 已选城镇。
3. 已选建筑。
4. 已选小队。
5. 无选择时的基础操作提示。

## 上下文状态

### 小队

- 左列：小队类型、已选数量、存活成员和按初始总生命计算的综合生命比例。
- 中列：当前状态、兵种克制关系和世界队徽拖动提示。
- 右列：移动、攻击移动和停止按钮，同时显示快捷键。

### 建筑

- 左列：建筑类型、生命比例、建造状态或生产队列数量。
- 中列：建造进度或最多五项的训练队列及当前项进度。
- 右列：该建筑可执行的训练命令；不可用项目保留位置并显示原因。

### 城镇

- 左列：所属阵营、专精、基础收入与人口。
- 中列：补给状态、发展状态、工程进度和当前专精效果。
- 右列：未专精时显示贸易、征募、要塞；已激活时显示降级；不可操作的中立或敌方城镇只显示公开信息。

原 `UStrategyTownPanel` 不再单独实例化，城镇内容并入统一底栏。旧类在新版 HUD 人工验收前保留，便于快速回退；本轮不删除其源文件。

### 建造模式

底栏上方显示当前建筑、价格、确认与取消按键。有效位置使用绿色，非法位置使用红色，并只说明一个主要原因，例如“超出领地”“地面不可导航”或“与建筑重叠”。

## 技术架构

采用“UMG 主界面 + Canvas 世界投影”的混合结构。

### `UStrategyHUDRoot`

新增一个原生 C++ `UUserWidget`，作为唯一的屏幕主 HUD，直接管理：

- 顶部资源栏。
- 临时通知区。
- 三列上下文底栏。
- 比赛胜负覆盖层。

控件在 C++ `WidgetTree` 中构建，保持现有项目结构，不新增大量子控件类。颜色、字号、间距、底栏比例和缩放规则集中为紧凑的 UI 样式常量。

HUD 每帧读取当前 `AStrategyGameState` 与 `AStrategyPlayerController` 状态并刷新显示，不保存权威游戏状态。选择、资源、队列、工程进度和胜负仍由现有运行时对象负责。

### `AStrategyHUD`

Canvas HUD 继续负责：

- 框选矩形。
- 世界小队徽记及拖动箭头。
- 世界生命条。
- 城镇专精图标与进度。
- 补给线。
- 建造放置投影。

现有世界徽记拖动下令逻辑和命中区域保持不变，仅统一颜色、边框和选中高亮。

### `AStrategyPlayerController`

玩家控制器仍是所有 UI 操作入口。HUD 按钮调用与键盘和右键相同的现有命令路径，不复制消费、训练、专精或下令规则。

需要点击目标的按钮只进入已有待命令状态：移动或攻击移动的目标仍由玩家在战场上指定。训练、停止、专精和降级按钮直接调用对应现有接口。

## 输入与焦点

- 主界面使用 `FInputModeGameAndUI`，保持鼠标可见。
- 按钮操作结束后将键盘焦点交还游戏视口，确保 WASD、滚轮和快捷键继续有效。
- `Esc` 暂停菜单保持最高层级；关闭后恢复左右键战场操作。
- HUD 不覆盖世界小队徽记的拖动命中区域。
- 无效操作不改变选择或当前命令状态，只播放一次现有无效反馈并显示一条短通知。

## 按钮与进度规则

- 可用按钮：深棕背景、金色边框。
- 悬停按钮：提高亮度并加强边框。
- 按下按钮：轻微下沉并使用内嵌边框。
- 不可用按钮：灰色但保留位置；悬停显示一个主要原因。
- 生命条使用绿、黄、红三个健康区间。
- 建设和训练使用金色进度，降级使用橙色进度，人口满额和无效状态使用红色。

## 分辨率适配

- 1920×1080 为设计基准。
- 1280×720 时整体约 85% 缩放，但正文不低于可读最小字号。
- 2560×1440 时控件保持合理最大尺寸，不随分辨率无限放大。
- 底栏左右保留 20–32 px 安全边距，宽度随窗口变化，三列比例保持不变。
- 长文本优先缩短措辞或在详情区换行，不压缩按钮文字和关键数字。

## 验证策略

为减少重复测试，分三批验证：

1. HUD 根布局、顶部资源、缩放与上下文优先级。
2. 小队、建筑、城镇、建造模式按钮，以及鼠标和键盘输入共存。
3. 最终编辑器构建、UI 定向测试、短时打包启动与人工视觉验收。

自动化测试覆盖纯状态映射、上下文优先级、生命比例显示、按钮可用性和缩放规则。人工验收覆盖 1280×720、1920×1080 与 1920×1200、三类选择对象、建造模式、暂停恢复、左右键、WASD、滚轮和世界徽记拖动。

本轮不重复完整对局测试；只验证 UI 没有改变已存在的建造、训练、升级、选择和命令接口。

## 分阶段实施

1. 建立 HUD 根控件、样式常量、顶部资源栏和空的三列底栏。
2. 接入小队、建筑、城镇与建造模式，停止实例化独立城镇面板。
3. 接入可点击命令、不可用原因、通知、胜负覆盖层和分辨率缩放。
4. 统一 Canvas 世界反馈颜色，完成最终验证与 Windows 候选包。

## 验收标准

- HUD 在 1280×720、1920×1080 和 1920×1200 下无重叠、裁切或竖向异常换行。
- 资源、人口、城镇、选择、生命、队列、升级与建造状态清晰可读。
- 小队、建筑和城镇切换时底栏保持固定布局。
- 按钮状态能够明确区分可用、悬停、按下和不可用。
- WASD、滚轮、框选、左右键、暂停恢复和世界徽记拖动均正常。
- UI 按钮与原快捷键调用相同规则，不产生重复扣费、重复训练或不同命令行为。
- 不可见敌方信息仍受现有迷雾规则限制。
