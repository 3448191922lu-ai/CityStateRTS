# M4-01 视觉与音效统一设计

## 1. 目标

在不改变经济、人口、建造、训练、占领、战斗、AI、寻路、迷雾和胜负规则的前提下，将当前基础几何体原型替换为风格统一、信息清晰的中世纪低多边形表现。玩家应当仅凭场景与声音辨认阵营、兵种、建筑功能、建造状态、命令类型、占领状态和主要战斗结果，不依赖调试显示。

M4-01 覆盖三类单位、全部建筑、首都与城镇、战场环境、状态反馈和音效。背景音乐、语音台词、音量设置界面及显示设置不在本项范围；设置界面留给 M4-02。

## 2. 风格与素材来源

### 2.1 视觉方向

采用兼顾战术辨识度和环境氛围的中世纪低多边形风格。Quaternius 资源作为主要造型来源，Poly Haven 2K 材质作为地表和建筑表面补充。角色保留 Quaternius 原始贴图，避免将写实 PBR 材质强行套用到角色后造成风格割裂。

阵营识别同时使用颜色与形状：玩家使用蓝色布料、旗帜和盾牌标记，敌方使用红色，中立据点使用土黄色。阵营色不覆盖整件模型，木材、石材、金属和皮革保留自然颜色。

### 2.2 选定资源

- [Quaternius Medieval Village MegaKit](https://quaternius.com/packs/medievalvillagemegakit.html)：首都、城镇、兵营、靶场、马厩、民居、箭塔、城墙、城门和环境模型。
- [Quaternius Animated Knight](https://quaternius.com/packs/knightcharacter.html) 与 [RPG Characters](https://quaternius.com/packs/rpgcharacters.html)：步兵和弓兵基础角色。
- [Quaternius Ultimate Animated Animals](https://quaternius.com/packs/ultimateanimatedanimals.html)：骑兵马匹。
- [Quaternius Universal Animation Library](https://quaternius.com/packs/universalanimationlibrary.html)：补充待机、移动、攻击和死亡动画。
- [Poly Haven](https://polyhaven.com/textures)：石材、木材、泥土和道路等 2K 材质，仅下载实际使用项。
- Kenney [UI Audio](https://kenney.nl/assets/ui-audio)、[Interface Sounds](https://kenney.nl/assets/interface-sounds)、[RPG Audio](https://kenney.nl/assets/rpg-audio) 和 [Impact Sounds](https://kenney.nl/assets/impact-sounds)：命令、界面、战斗、施工与破坏音效。

Quaternius 与 Poly Haven 选定资源使用 CC0 许可。Kenney 上述四个音效包的官方页面明确标注 Creative Commons CC0。实施时仍为每个下载包记录名称、来源页面、许可证和下载日期。

不把完整素材包复制进项目，不导入示例场景、重复格式、未使用贴图或音乐。

## 3. 视觉语言

### 3.1 单位

- 步兵：盾牌与近战武器形成较宽轮廓，在等距视角下优先辨认防线角色。
- 弓兵：弓、箭袋和较轻服装形成细长轮廓。
- 骑兵：马匹是主要识别轮廓，骑手与马组成一个现有游戏单位。
- 三类单位继续沿用当前生命、伤害、人口、碰撞、导航和小队规则。
- 每名单位具有待机、移动、攻击和死亡四种基础动画状态；不加入复杂连招、布料模拟或布娃娃。

小队 HUD 徽记、生命比例和拖拽操作保持现有行为。小队生命比例仍按存活成员当前生命总量除以小队初始总生命量计算，成员死亡不会降低生命上限。

### 3.2 建筑与据点

- 兵营：方正、厚重，突出近战训练功能。
- 靶场：靶标、箭架或开放训练区域清晰可见。
- 马厩：围栏、棚架或马厩门形成明确轮廓。
- 民居：高屋顶、小体量，与生产建筑区分。
- 箭塔：高位平台和射击方向明显。
- 城墙：连续厚重墙段，保持现有实体阻挡。
- 城门：跨在墙线上，外形保留明显通道，继续只允许己方单位通过。
- 首都：体量最大，使用多面旗帜强化阵营归属。
- 中立城镇：体量小于首都，使用土黄色旗帜；被占领后切换为所属阵营旗帜。

建筑施工期间显示半透明、低饱和外观和进度条，并辅以少量尘土。施工完成时恢复正式材质并播放一次完成反馈。施工表现不改变碰撞、计时或建造规则。

### 3.3 环境

两张地图使用相同材质与植被语言，但保留地形区别。基础地图突出开阔草地与道路；河谷地图突出泥土河岸、石质渡口和河谷植被。树木、岩石、灌木和道路装饰不得遮挡主路线、建筑落点、控制点轮廓或小队 HUD。

环境装饰优先使用实例化静态网格，控制 Draw Call。地形和大型遮挡物继续遵守现有导航及禁建区数据，不借视觉替换改变通行路线。

## 4. 状态与命令反馈

- 移动命令：绿色地面箭头或标记，约 0.8 秒淡出。
- 攻击移动：橙色标记，形状区别于普通移动。
- 指定攻击：目标处显示红色标记。
- 受伤：短促材质闪烁，不持续改变阵营色。
- 弓箭与箭塔：使用轻量箭矢轨迹和命中反馈。
- 单位死亡：播放短动画后快速淡出或产生少量尘土，不使用布娃娃。
- 建筑摧毁：简短尘土和碎屑表现，随后沿用当前清理流程。
- 据点占领：显示进度环；争夺时闪烁；完成后切换旗帜和阵营色。
- 胜利与失败：保留当前 HUD 流程，增加一次明显但不过长的视觉与声音提示。

颜色与形状同时编码，避免只依赖红绿色差异。粒子数量、寿命和并发量以双方各 60 人口交战时仍保持可读为上限。

## 5. 音频设计

不加入背景音乐或语音台词。音频风格为“命令反馈清晰、战斗与施工写实克制”。

最小事件集合如下：

- 选择确认。
- 移动命令。
- 攻击移动或指定攻击。
- 无效操作或无效放置。
- 建筑开始施工与施工完成。
- 单位训练完成。
- 据点开始争夺与占领完成。
- 近战命中、弓箭发射与命中、骑兵蹄声或冲击。
- 箭塔射击、建筑受击与摧毁。
- 胜利与失败。

选择和命令音每次玩家操作只播放一次，不按单位成员数量重复。UI 与命令确认音使用 2D 播放；战斗、施工和破坏声音使用带距离衰减的 3D 播放。高频战斗声音使用并发限制和短冷却，避免大规模交战时堆叠成持续噪声。

## 6. 技术架构

### 6.1 数据资产

扩展现有 `UStrategyUnitDataAsset`，保存单位类型专属的骨骼网格、材质、视觉比例、待机/移动/攻击/死亡动画，以及需要的投射物和局部音效引用。骑兵额外保存骑手网格和骑手动画引用。

扩展现有 `UStrategyBuildingDataAsset`，保存建筑正式网格、材质，以及箭塔等类型需要的专属投射物和攻击音效引用。建筑费用、施工时间、生命、占地、人口奖励与训练列表保持原字段和数值；通用施工反馈仍由全局表现数据提供。

新增一个 `UStrategyPresentationDataAsset`，集中保存跨类型共享的表现资源：

- 玩家、敌方和中立阵营材质及旗帜。
- 三类命令标记。
- 通用受击、施工、占领、胜负效果与声音。
- 首都、城镇和地图环境资源引用。
- 音频衰减与并发配置。

`AStrategyGameState` 只负责加载并提供这一资源定义，不处理具体动画、粒子或音频播放。

### 6.2 运行组件

- `AStrategyPlayerController`：在原有下令成功路径上生成一次命令标记并播放一次确认音。
- `AStrategyUnit`：启用 `ACharacter` 继承的骨骼网格组件，根据现有移动和战斗状态切换动画；骑兵附加一个骑手骨骼网格组件。
- `AStrategyBuilding`：继续使用现有碰撞、施工、生产和箭塔逻辑，只负责同步网格、施工外观及局部效果。
- `AStrategyControlPoint`：负责首都和城镇外观、旗帜、占领环与占领音效。
- `AStrategyMapTerrain`：承载两张地图共同的地表材质与实例化装饰，不改变地图定义中的路线、禁建区或导航障碍。
- `AStrategyHUD`：保留现有投影式小队徽记、生命条、拖拽箭头、资源和操作信息，仅统一颜色、字体和状态图形。

不增加事件总线、通用表现框架或插件模块。表现代码直接挂接现有成功路径，以保持结构紧凑。

### 6.3 数据流

```text
玩家输入
  -> StrategyPlayerController 生成原有 FStrategyOrder
  -> 命令成功后生成一次标记和确认音
  -> StrategySquad 将命令分发给成员
  -> StrategyUnit 根据移动/攻击状态驱动动画
  -> 命中事件驱动攻击、受伤和死亡反馈

建筑或据点状态变化
  -> 原有施工/占领/摧毁规则完成状态变更
  -> 对应 Actor 更新网格、材质、旗帜、特效和声音
```

表现层只读取规则结果，不反向决定命令是否成功、伤害数值、占领速度或单位通行。

### 6.4 迷雾约束

生成敌方世界特效前，通过现有 `IsVisibleToFaction` 检查玩家视野。附着在敌方单位或建筑上的网格、粒子和状态表现随 Actor 可见性一起隐藏。不可见区域不播放可定位敌军的战斗、施工或移动声音，避免声音和粒子泄露情报。玩家自己的 2D 操作确认音不受迷雾影响。

## 7. 缺失资源处理

M4 正式 Data Asset 中的模型、材质和基础动画视为必需配置。不添加基础几何体、默认材质或静默音效作为运行时回退。统一资产审计负责在打包前发现空引用、错误骨架、缺失动画和未登记来源；通过审计后，运行时按配置直接使用资源。

音效允许为空的事件仅限设计明确未要求声音的装饰性表现。若选定声音试听不合适，在已批准的 CC0 音效包内替换，不自动扩大素材来源或许可范围。

## 8. 实施阶段

1. **M4-01A 素材接收**：下载、解包、登记许可，筛选实际使用的模型、贴图、动画和音效。
2. **M4-01B 场景与建筑**：导入共用材质，替换环境、据点和全部建筑，保持导航与占地不变。
3. **M4-01C 单位与动画**：替换步兵、弓兵、骑兵并接入四种基础动画状态。
4. **M4-01D 反馈与音频**：接入命令、建造、占领、战斗、摧毁及胜负反馈，统一 HUD 色彩。
5. **M4-01E 集中验证**：执行资产审计、编译、针对性自动化测试、PIE 验收和 Windows 打包冒烟测试。

实施按上述顺序进行，阶段内部不为每个单独资源重复打包。

## 9. 验证与验收

为降低测试频率，只设置以下集中检查点：

1. 素材导入结束后执行一次资产审计，检查引用、骨架、动画、许可证记录和未使用资源。
2. 所有代码与内容接入完成后执行一次 Development Editor 编译和受影响的 Strategy 自动化测试。
3. 在 PIE 中集中检查两张地图、三个兵种、全部建筑、三种命令、施工、占领、迷雾、战斗和胜负表现。
4. 生成一次 Windows Development 候选包，检查独立启动、正常对局、重新开始和退出。

M4-01 验收标准：

- 玩家无需调试显示即可辨认双方阵营、三类兵种和全部建筑类型。
- 城墙连续、城门通道明确，原有阻挡和通行规则不变。
- 待机、移动、攻击和死亡动画与实际状态一致。
- 普通移动、攻击移动和指定攻击的标记在颜色和形状上可区分。
- 施工、占领、受击、箭塔攻击、死亡和摧毁反馈清晰但不过度遮挡战场。
- 迷雾内敌军不会通过模型、特效或可定位声音泄露。
- 大规模交战时音效不过载，粒子不会明显妨碍选择与下令。
- 两张地图均能在独立包中完成现有整局流程，玩法数值与规则没有非预期变化。

## 10. 明确不做

- 背景音乐、角色语音和剧情演出。
- 新兵种、新建筑、新技能或数值平衡调整。
- 复杂动画状态机、动作匹配、布娃娃和物理破坏。
- 昼夜循环、动态天气、高密度植被或电影级后处理。
- 通用音频中间件、表现事件总线或独立插件。
- M4-02 的音量与显示设置，以及 M4-03 的最终交付整理。
