# 河谷争渡第二张遭遇战地图设计

## 目标

在不引入新玩法规则和外部资产的前提下，为《城邦争霸》增加第二张可完整游玩的遭遇战地图。地图通过河流、桥梁、浅滩和阻挡地形改变进攻路线，并继续复用现有经济、AI、建造、战斗、迷雾和胜负系统。

## 地图布局

- 关卡名：`LVL_RiverValleySkirmish`。
- 地图范围约 `18000 × 14000 cm`，保持在现有镜头和战争迷雾覆盖范围内。
- 玩家主城：`(-7000, 0, 0)`。
- AI 主城：`(7000, 0, 0)`。
- 玩家初始步兵：`(-5600, 0, 100)`。
- AI 初始步兵：`(5600, 0, 100)`。
- 中央城镇：`(0, 0, 0)`，位于中央浅滩。
- 北部城镇：`(-2200, 3900, 0)`，略偏玩家侧。
- 南部城镇：`(2200, -3900, 0)`，略偏 AI 侧。
- 据点布局采用绕地图中心旋转 180°后的对称关系，保持双方公平。

## 路线与地形

- 河流纵向贯穿中部。水面和河道障碍使用引擎基础几何体与动态导航障碍构成，不允许普通单位进入。
- 北桥中心约为 `(0, 3000)`，南桥中心约为 `(0, -3000)`；通行宽度约 `1800 cm`。
- 中央浅滩中心为 `(0, 0)`，通行宽度约 `1200 cm`，是距离最短但最拥挤的路线。
- 河道由多段阻挡体拼成，并在两座桥和浅滩处留下导航缺口。
- 林地和岩石仅作为阻挡与路线塑形，不提供高低地、伤害、视野或资源加成。
- 双方均可在桥头领地内建造城墙、城门和箭塔，但整条河道走廊均为禁建区，避免封死桥面或浅滩。

## 地图配置架构

新增紧凑的 `FStrategySkirmishMapDefinition`，集中保存：

- 当前关卡名称。
- 双方主城和初始小队位置。
- 三座中立城镇位置。
- 战争迷雾最小、最大边界。
- 是否生成河谷地形。
- 地图专用禁建区域。

`StrategyGameMode` 根据当前关卡名称取得定义，再生成据点、小队、AI、迷雾和地图地形。原地图继续使用原有坐标；河谷地图使用本设计坐标。PIE 自动添加的关卡名前缀不影响识别。

## 运行时地形

新增无 Tick 的 `AStrategyMapTerrain`：

- 使用 `/Engine/BasicShapes/Cube` 和动态材质构建河道、桥面、浅滩、岩石及林地。
- 河道、岩石和密林启用实体碰撞并影响动态导航。
- 桥面与浅滩只负责表现；其下方保留可导航地面。
- 所有生成对象归属于一个地形 Actor，退出或重开关卡时由世界统一清理。

地图地形只改变空间通路，不改变单位属性、移动速度、索敌、AI 决策频率或建筑数值。

## 建造限制

`AStrategyGameState::CanPlaceBuilding` 在现有领地、导航和重叠检查之前，先检查地图定义中的禁建区域。河谷地图将中部河道走廊设为禁建区，因此普通建筑、城墙和箭塔均不能直接建在河流、桥梁或浅滩上；城门仍只能由己方完工城墙升级获得。

## 关卡与重开

- 保留 `LVL_CityStateSkirmish`，创建独立的 `LVL_RiverValleySkirmish`。
- M3-01 验收期间把河谷地图设为编辑器和打包默认地图。
- `R` 键在胜负结束后重新加载当前关卡，不再固定打开第一张地图。
- 本阶段不增加主菜单、选图菜单或随机地图逻辑。

## 验证边界

按照用户要求降低自动测试频率：先集中写入地图选择、禁建区域和当前关卡重开所需测试，确认一次预期失败；完成全部实现后集中执行一次编译与规则测试，再进行一次 Windows 打包启动检查。最终人工验收覆盖两张地图各一整局，以及桥梁、浅滩、绕路、禁建和 `R` 重开。

## 非目标

- 不修改三兵种、经济或建筑数值。
- 不新增高低地加成、涉水减速、桥梁摧毁、资源采集或地图事件。
- 不下载插件、美术或音频资产。
- 不重构现有玩法模块，不增加通用地图框架。
