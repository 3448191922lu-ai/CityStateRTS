# M5-04 城邦战术 HUD 候选

## 当前状态

M5-04 已完成实现、编译、自动化、打包、启动检查和人工 UI 验收，状态为完成。候选包位于 `Builds/Windows_M5_UI`。

## 设计与交互

- 使用原生 `UStrategyHUDRoot` 统一顶部资源、通知、A1 平衡型整底栏和胜负覆盖层。
- 底栏根据空选择、小队、建筑、城镇和建造模式切换 24/44/32 三列上下文。
- `AStrategyHUD` 只保留框选、世界小队徽记、生命条、城镇图标、补给线、拖动箭头和建造进度。
- 按钮复用控制器和比赛状态的原命令路径；点击后恢复游戏视口焦点。
- 训练按钮显示费用与禁用原因；普通建筑放置显示地图、领地、导航和重叠的单一失败原因。
- 小队综合生命按存活成员当前生命总量除以小队初始总生命量计算，成员死亡不降低上限。
- 通知最多保留三条并在三秒后消失；无效操作继续播放原有音效。
- 按钮仅在选择、资源、队列或模式变化时重建，实时文本与进度仍逐帧刷新。

- `Windows_M3_NavFix3` 是超过五版本保留上限的最旧候选，将在 M6 最终候选生成后与其他超额旧候选一并清理。

- 三种分辨率均已通过人工验收；M5-04 已完成。

## 文字抖动修复

- 已排除单纯的小数缩放假设：固定 1:1 像素缩放后人工观察没有改善。
- 人工观察确认抖动只在对局运行时持续，比赛失败、动态状态停止后文字恢复稳定。
- 实际触发源是金币增长时每跨过 1 金币都会改变指令签名，导致整组指令按钮被销毁并重建；顶部资源整行居中也会随动态数字字宽变化重新定位。
- 指令签名现只在跨过可购买/不可购买阈值时变化；顶部动态资源行取消自动换行并使用固定左起点。
- 相同可购买状态下金币个位变化不会触发布局重建；新增定向回归后 `RTS.Strategy.UI` 9/9 成功。
- Windows Development 候选包已重新构建；发布清单 49 个文件，哈希复核不匹配数为 0。
